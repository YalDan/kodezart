**Unresolved backend limitation — existing in-flight requests are not fenced.** The actual adapter checks marker ownership before issuing a comment mutation, but the backend does not compare a fence token atomically when it applies that mutation. Root's unchanged-production-adapter probe pauses the outgoing old write at the server boundary, advances beyond expiry, acquires a successor, resumes the old write and observes that it lands while the successor grant remains. I inspected its source and passing characterization log. Consequently the full KOD-386 criterion remains unmet for this race. The patch still improves production behavior by acquiring the declared set, checking current ownership, renewing explicitly and draining issued operations before release. The proven limitation does not prevent integrating those bounded behaviors; no claim of exclusive backend execution accompanies this verdict.

**Existing broader contracts remain open.** Lifecycle on_dequeue/on_pull_request/on_verified_merge/on_run_failed state changes predate this patch and remain outside the terminal-comment lease operation. ## Source and oracle assessment

RunSurfaceLease owns request lifetime, delegating acquisition/arbitration to the existing tracker port. It rejects blank job IDs and empty sets, allows one entry, performs explicit renewal, latches loss inactive and never reacquires after loss. Loss carries the known job/set instead of inventing an individual surface/current holder from an uninformative None return. The unchanged owned_tasks.settle implementation retains the task, drains repeated caller cancellation and propagates cancellation after the owned request settles. Broad BaseException handling exists only to clean up potentially committed acquisition before reraising; ordinary programming errors are not normalized into successful outcomes. A cleanup backend failure can mask the original exception and leave a grant until expiry: no universal cleanup guarantee is asserted.

The actual constructor in composition/passes.py supplies operation marker prefixes and config.tracker.surface_lease_seconds. TrackerLifecycleWriter validates run_outcome configuration during construction. Its terminal path uses the queue's actual job ID, a per-job marker and singleton issue-comment surface; gates the same DERIVED payload, renews after gating, settles the comment write, then releases. It does not introduce a timer, registry, parallel scheduler or second state ledger. LinearMcpTracker checks existing ordered grants and returns typed refusal for absent/wrong/expired ownership, including no-op upserts. Protected or unknown comment authors are not overwritten. Both production upsert_comment consumers (lifecycle and escalation) were migrated; the remaining occurrences are port/adapter definitions.

The actual-constructor oracle traverses build_job_queue, AsyncioJobQueue, build_dispatch_passes, LifecycleWatcher and the real LinearMcpTracker; only the raw tool/server boundary is doubled. It observes the generated queue job ID as holder, configured 321.5 acquisition and renewal, the held grant at write, payload identity and release. Other focused controls exercise contention, absent holder, expiry, no reacquisition, gate failure and repeated cancellation across acquisition/renewal/write/release. The overlap oracle permits zero successes; separate positive acquisition and disjoint-write controls supply the positive case.

Fixture migrations acquire explicitly through a helper and pass its holder; no fake automatically grants ownership. Because that helper uses RunSurfaceLease, those fixture tests alone would be circular evidence for owner correctness. The actual-adapter boundary controls above provide the independent observation. Comment-page fixtures include real lease rows and coherent clocks/identity; extra reads measure the ownership check. Escalation replay preserves business payload/comment identity/label assertions while excluding transport timestamps changed by lease markers. It does not claim zero transport writes on replay. Integration must preserve the independently approved neutral-port exception expectations where this branch overlaps taxonomy migration 9b90086.
