The unchanged-HEAD cancellation positive still propagates cancellation and releases the workspace. Smallest correction must preserve original cancellation/failure while retaining evidence when local identity changed.

2. **The dirty path pushes after authority changes during commit.** `GitChangePersister._persist_dirty` calls the current-source guard before `git.commit`, then awaits commit and immediately pushes. The independent boundary wrapper completes the real local commit, changes a current tracker Check, and returns; the obsolete commit is published and a result event emitted without rereading authority. The unchanged-source paired control successfully commits/pushes. This is before push is issued, not an impossible atomic-backend requirement. A prepublication check needs the actual harness-produced SHA; calling the original-HEAD verifier unchanged after commit would incorrectly reject the harness's own authorized commit.

Nevertheless `_evaluate_node` manufactures an all-false `AcceptanceCriteriaOutput`, appends a zero-pass/all-failing `IterationRecord`, emits `WorkflowIterationEvent`, replaces pending criterion failures and flips plateau false→true. This conflicts with the live97 trajectory-preservation requirement even though the trajectory type and fold function were not edited.
