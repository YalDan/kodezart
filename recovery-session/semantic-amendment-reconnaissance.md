## Source foundation and smallest interface

Canonical has no `chains/amendment_reconciler.py`, no `types/domain/amendment.py`, no AmendmentVerdict, no PinnedRulingSet consumer, and no amendment gate. `services/assertion_drift.py` only produces observed assertion changes; it must not become a second semantic owner.

Use `services.audit_sessions.judge_in_workspace` in an `owned_workspace` at a fully resolved immutable base, with `SessionType.TICKET_FIRE`, `session_id=None` (already enforced), NO_SUBAGENTS and EVALUATION tools. Check clean exact HEAD and absence of replace refs before and after execution using existing git observations. `FreshAuditSession` already owns this mechanics but hardcodes scheduled-pass context/audit errors: either use its lower shared helper as Organize admission does, or serialize a small generalization of the existing helper. Do not add a parallel runner abstraction or abuse scheduled-pass identity for fire.

Reuse KOD66's `FindingEvidence`, `classify_finding`/`grounded_finding`, shared `reconcile_findings` and `minimal_conflicting_subsets`, and validation-findings rendering conventions. These check evidence completeness, fault-line consistency and exact identities; they are not a semantic theorem prover. Do not reuse authored `CriterionFinding`/`Contradiction` directly: their restored AC-n wire constraints are intentionally authored-only. Native subjects use existing `CriterionId` per [settled KOD763](https://linear.app/duckburg/issue/KOD-763#comment-24370a9c-aed8-4285-ae2b-9cd4ffadd1ee), with no key map or new CriterionKey. Ruling subjects use existing `RulingId`; `RulingRecordReader` already distinguishes confirmed-empty from malformed/unreadable/duplicate records and retains native comment addresses. [KOD635](https://linear.app/duckburg/issue/KOD-635) preserves ruling identity for resolution changes, not question changes.

Proposed coherent new `types/domain/amendment.py` contains:

- Discriminated criterion/ruling subject (existing CriterionId/RulingId), enumerated claiming stage and a DeviationClaim carrying departure and optional typed capability, with no claimant reasoning/transcript.
- Four exhaustive grounds and four refusal reasons, discriminated structured judgment arms. AMENDED-candidate carries ground, independently obtained refutation, actual checked repository references and proposed correction. UPHELD carries exactly its reason and reason-specific evidence/capability. Mutual evidence names a distinct, current minimal subset, not an arbitrary pair. Unknown, duplicate, wrong-parent or substituted identities refuse before any side effect.
- A distinct applied result/receipt keeps semantic assent separate from a confirmed landed amendment. Do not return a final AMENDED verdict before tracker correction, untick, canonical readback verification and branch gate complete. This is an internal phase distinction, not a third public verdict.
- Pure repeat fold over retained verdicts keyed by subject kind/id/reason; no mutable aggregate or LoopTrajectory change.

Proposed required constructor collaborators: narrow criteria/comment readers, existing GitService + WorkspaceProvider + AgentRunner + PromptSetProvider + SkillsSelection; explicit configured correction bound if redispatch is enabled. A single `judge(claim, current_subjects, pinned_rulings, repository, resolved_base_sha, declared_capabilities, run_identity)` produces validated semantic evidence. Its owner rereads those snapshots itself or validates a typed owner-created snapshot; accepting a caller's unverified arbitrary object must not become an authority shortcut. Deterministic postvalidation checks identity, base, evidence addresses, supported ground, fault-line/reason pairing and required references. Actual semantic truth comes from the fresh refuter session, not path heuristics.

## Counterexample and test plan

1. Preserve the real two-commit Git reader fixture. For each ground, all formerly decisive path/quote facts hold but the semantic ground is false: a missing requested file can be implemented; a criterion prohibits an absent quoted line; two distinct demands apply to different conditions and coexist; a rule requires the quoted construct or both criterion and rule prohibit it. Fresh independent judge returns UPHELD and real tracker/branch remain byte-identical. Pair each with a genuinely impossible/contradictory/false-premise/necessary-rule-breach repository case. Boundary scripted model outputs prove wiring only; recorded live model evaluation is needed to claim semantic reliability, and must not be replaced by an oracle mirroring the predicate.
2. Actual dispatched schema, actual prompt provider and exact base workspace: assert no author session, transcript or reasoning; different HEAD content cannot influence base judgment; wrong full SHA/dirty tree/replace refs/post-session mutation refuse, cancellation/programming errors escape.
3. Unknown/duplicate/foreign subject, criterion-vs-ruling type confusion, stale revised Check, foreign/minimally invalid mutual subset, malformed checked refs, unsupported ground and wrong verdict-reason mixtures all refuse before writes. Typed mypy counterexample rejects bare str ruling identity.
4. Environment missing vs supplied vs unclaimed capability; no measurement vs affordable vs uneconomic measurement; none amends. Cost instruments leave branch/head/files unchanged; uneconomic refusal carries actual measurement to the existing escalation owner.
5. Production constructor path with boundary doubles only: claim reaches the real fresh judge, refusal blocks actual commit even when tests are green, author cannot write approved labels or criterion Done. Approved amendment preserves native identity, reverses state and clears Evidence/rederivation before commit, and uses existing canonical reread/fresh verification/bounded repair. Readback failure, stale revision, exhausted repair, lease loss and unknown write outcome prevent branch advance; replay neither resends an uncertain write nor overwrites an already amended body.
6. Two real producer verdicts reach one actual iteration report beside failures; same subject/different reasons remain distinct; mixed ruling/criterion ids cannot collide; list remains source of truth and trajectory unchanged. No seeded-state-only success oracle.
