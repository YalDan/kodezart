## Finding and proposed boundary

The reusable record model, codec, current reader, lease owner and write-back verifier exist. **No production call constructs LaneRunState.** The current committing path also cannot supply KOD681's complete commit rows: it discards the existing persistence receipt's message/source and creates an IterationRecord only after the evaluator runs. Recording a first push must not manufacture the future evaluation's passed count or failures. This is the same truthfulness distinction independently enforced by the native amendment correction.

The smallest credible runtime slice is one required native **commit-and-record operation**, invoked within AgentService while it still owns the writing workspace. That operation delegates Git mutation to the existing ChangePersister, then writes and verifies the record before it can return success. Ralph's actual execute node supplies frozen prior trajectory and addressed lane facts; it receives the operation's actual persistence receipt. There is exactly one LaneRunState construction call inside that owner. An optional post-stream writer or a terminal-only update does not meet KOD687.

This is one harness operation, not an atomic Git-plus-tracker transaction. A remote push followed by a tracker outage still creates a detectable record gap. No adapter CAS or fencing guarantee is available, and no new transaction/event authority is proposed.

## Shared interface proposal for root agreement before writes

1. **An explicit lane commit context**, supplied by the actual runtime: native issue/lane identity, parent queue job_id, exact repository/base, current LOOP and actual branch-origin facts, previous complete typed trajectory, and the current association set. The queue job is carried explicitly through ExecutionContext/prepare/Ralph; existing scope metadata binds replay but is not decoded ad hoc as write authority. Bind branch association run_id to this actual job id. Keep RunIdentity as the independent existing run-record identity.

2. **One required native operation collaboration.** Suggested protocol `LaneCommitOperation.persist(*, workspace_path, persist)` accepts the existing zero-argument async ChangePersister call supplied by AgentService and returns its actual result only after record verification. A bound operation is created by the record owner from the context above. Native AgentService entry must refuse if no operation is composed; the authored path keeps its existing explicit behavior. This avoids reproducing ChangePersister's long argument list or moving Git algorithms into a tracker writer. The final name/signature belongs to root/native interface agreement, not this research.

3. **A truthful commit fact handoff.** Carry the actual PersistResult through the existing result/state handoff instead of discarding it. Reuse LaneCommit as the complete SHA/subject/native-issue fact, taking subject from the actual receipt's message first line. Prefer one atomic optional commit fact on IterationRecord, with commit_sha derived from it, over three independently optional fields. This would require a deliberate migration of existing producers/checkpoints/consumers; missing old subjects/issue identities must refuse or be explicitly migrated, never guessed. At push time only a pending commit fact exists. Project prior graded records' commit facts plus that actual pending fact into the branch record; attach the same fact when evaluation really happens. **Literal681 equality to already-graded records cannot hold at the first-push instant under current sequencing.** The bounded implementation can make equality true after grading while exposing the pending receipt, but must not claim full681 until root accepts that interpretation or coordinates a coherent pending/graded trajectory shape. A second commit ledger, fake zero-pass iteration, or Git-history observer is not proposed.

4. **Use the existing universal writer.** A narrow record wrapper, if needed, should follow the accepted alarm pattern: configured native `record_lane_run_state(issue_key, record, holder)` forwards to the same private upsert algorithm with a parser precondition on the exact fresh existing TrackerComment it will mutate. This prevents overwriting damaged/changed record history read after an earlier check. Do not add another upsert/lease implementation. Extend the existing LaneRecordReader with a shared `read_if_present` path (strict read delegates and retains absence refusal) rather than catching reason strings for first creation. Root owns any new port/error contract; the proposed wrapper does not create LaneRunState.

## Operation sequence and failure behavior

Bind the complete declared write set before mutation: the lane's configured run_state marker and its canonical run_event stream marker. Shared container surfaces and criterion state/Evidence are absent from this slice. Validate both configured purposes and live lease duration at production construction, without default marker prefixes. Preserve historical associations from the current record, validate per-job role identity, and refuse conflicting/missing history instead of silently replacing it.

The operation acquires once under the actual queue job, reads current addressed record/event evidence, and invokes the existing guarded persister. Native before_commit/before_publish authority remains the native owner's policy. No new generation/evaluation/refutation is added. After a successful push receipt, collect exact remote head and base-relative diff facts using existing ports; a required successful record asserts remote=head only after that actual observation. Recheck branch/source identity after awaited content gating, renew explicitly, then write through the universal holder/author path and existing WriteBackVerifier. Judge refutation may repair the representation from the same real facts within configured rounds; it cannot invent replacement facts. After verification, re-read relevant current head/record before returning the receipt; lease loss is typed and never triggers reacquisition.

The normal first push posts the existing FIRST_PUSH through the one canonical append method, separately from the record edit. The tenth push posts nothing. FIRST_PUSH already has a declared vocabulary publisher and NO_TRANSITION requirement; that is a tracker-state rule, not a ban on its notifying comment. Do not create a second event enum/list/table/applier. **Complete679 still needs a bounded publisher contract:** the current port deliberately treats equal events as distinct, carries no per-run occurrence identifier and has no holder enforcement. Root must approve the precise existing-publisher first-push occurrence/retry guard, including first-ever lane versus later run semantics. Do not deduplicate every equal event, stuff a job/SHA into subject_key, or add an alternate event marker/body. If the current lane identity is chosen as the first-push occurrence, fresh full stream reads under its lease can suppress a previously observed FIRST_PUSH; that must be an explicit rule, not an inference applied to all events.

For replay, the exact persisted receipt/record native identity is compared before calling the agent or committing again. An already-recorded identical receipt is a no-op; an existing confirmed first-push occurrence is not reposted. Successful push with failed record/event acknowledgement must be retained as an incomplete operation, never emitted as ordinary persistence success. Read back before retrying an ambiguous write. Current persister's None arm proves only local=remote, not that the record/event obligation completed, so it cannot silently clear a prior incomplete obligation. Missing commit metadata after a crash is a typed gap, not permission to regenerate a new commit or reconstruct grades.

For cancellation, use current owned-task settlement around operations still using the workspace/lease; wait before cleanup and retain the original cancellation. Preserve the workspace/receipt once commit effects may exist, including the no-returned-SHA window reproduced on2e7. Do not mask cancellation with a later ownership or logging error. A hard process death between Git and tracker remains a detectable gap. On restart compare the addressed record's head with the actual published branch using read_remote_head; absent/unreadable record and unequal head are explicit observations. Keep existing count/rows alarm as its current narrower predicate; no new alarm/event authority is needed just to refuse an unpaired commit. Automatic repair from missing historical facts remains out of scope.

PR facts are read from the existing PRStateReader when an actual known PR identity exists; explicit None before first PR is valid. Never fabricate an open PR from a URL lookup, use terminal prose, or widen LanePR for unrelated policy. Whole-run association persistence/query/re-entry and post-PR refresh remain separately measurable; this first commit slice must not claim their complete runtime coverage.
