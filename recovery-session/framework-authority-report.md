2. Ranking: `domain/dispatch.py:205 select_top_ranked`

The function orders existing eligible facts by domain priority (urgent first, none last), then full-precision oldest creation time. Only an exact tie calls the injected draw, over sorted tied keys. Empty input returns None; the result records the tied set and winner. F1 tests each priority, oldest-first, exact-time ties, reported draw, and deterministic order below a tie.

A tracker-capable session can choose a key, explain a priority exception, or use exactly the same policy. A typed `winner_key` plus evidence is feasible. Replacing the ranker with free selection loses the declared priority/age contract unless the returned key is checked against it. If checked, the policy arithmetic still exists as validation rather than selection. Removing the ranker with no substitute breaks FireDispatcher’s selection and F1 ranking/report assertions.

Its reproducibility is bounded: two legal draws over the same A/B snapshot produced A and B in P. The tied set alone does not reproduce the selected winner; the recorded winner does. Uniformity is supplied by the production random-choice dependency, not proven by the function’s type. An injected draw returning OUTSIDE is accepted by this function. This is a narrow precondition/validation gap if its draw seam becomes an agent seam, not evidence that the production random-choice callable currently returns foreign keys.

3. Issue tree and whole-read refusal: `domain/issue_tree.py`

`index_issue_tree` rejects duplicate/missing identities, missing parents, disconnected/cyclic parentage and an internal parent of the root. `SubtreeClosure` computes a gap across every descendant, requires each deliverable to have a direct criterion family, treats tracker/decision records as zero-gap leaves, and refuses criterion/record children. A parent workflow state is not its subtree’s finishedness.

`EmptyFireCriteriaError` at line 92 is raised for an addressed deliverable with no criterion family. `open_criteria` at line 63 raises `ScopeSupersessionReadError` for canceled/duplicate criteria: this path has no native supersession-reference reader and refuses rather than inventing a cancellation meaning. Exceptions propagate out of readiness/whole scope reading; the code does not produce a partial ready set. The refusal is demand-driven: F1 confirms an unapproved canceled lane need not force an unused supersession read. F1 also confirms an approved empty deliverable refuses, missing supersession refuses, a completed-looking parent over an open descendant stays open, and changed source facts abort the coherent read.

A session with complete tracker access can assemble the tree and return gap/closure or a typed refusal with criterion keys. It cannot obtain a missing native reference merely by being a session. It could judge prose describing supersession, but that changes the source of authority. If its proposal is checked for complete native membership, tree shape, exact gap and reference availability, those contracts remain encoded somewhere. If it is allowed to skip only the bad lane, that changes the present whole-read refusal policy and the unresolved approval/filtering contract.

Removal consequences: without the empty-family refusal, an unconfigured deliverable can falsely look complete; without the supersession refusal, missing evidence can falsely discharge canceled/duplicate obligations or escape as an incidental lookup error. Removing closure or replacing it with parent state loses out-of-filter descendant obligations and blocker discharge equivalence. F1 supplies the concrete contrary fixtures; no live agent substitute was benchmarked.

5. Topology and its dual blocker rule

`domain/topology.py:42 plan_topology` validates complete identities/dependency facts, rejects missing candidates/targets and cycles, deduplicates blockedBy edges, propagates effective priority backward from dependents to prerequisites, and returns ready/blocked partitions. Iterative traversal handles deep graphs without recursion limits. Parentage, related and reverse edges do not create dependencies. Ready items sort by effective priority and age; exact ties keep snapshot order, unlike the separate unscoped random draw.

The dual rule is real policy, not a framework requirement. Omit `blocking_issue_keys` and an open workflow-state target blocks. The scope caller `chains/scope_walker.py:74` supplies the set only for **in-scope** blockers whose criterion subtree remains open. F1 confirms that an outside-scope open blocker is not an in-scope readiness constraint, while its dependency facts can still exist for planning/base purposes. Therefore “all open blockers always block” is false for the scoped path. This is a behavior decision with an executable oracle, not something this report silently normalizes.

Four withdrawn observations: evidence verdicts

1. **“A value the tracker already answers is cheaper read than judged.” Confirmed narrowly for incremental calls over an already loaded snapshot; not established as a universal latency/cost claim.** F1 clauses consume typed values with no model call; empty scope avoids further tracker reads, while blockers and missing placement resolution do cause I/O. A judgment call would add a call only if one is not already running with that context. No actual model-token/latency comparison was run. The evidence supports avoiding redundant reacquisition, not a categorical agent prohibition or a total-cost ruling.

2. **“Ownership arbitration cannot be a session because it may answer yes twice.” Refuted as stated.** A session can call the same atomic/fenced port operation and return its typed result. F2 demonstrates one lease for simultaneous competing holders and refusal/loss on stale renewal in the fake/scripted backend fixtures; it does not test a model race or prove the live vendor’s atomicity. What fails is treating self-reported ownership or a prior read as the exclusion mechanism. That failure also applies to ordinary deterministic check-then-write code. The scoped-read double-check explicitly makes no transactional-lease claim. KOD-747’s current direction removes lane claim clocks while retaining surface leases; this report neither revives lane leases nor substitutes old quiet-board tests for adversarial live evidence.

3. **“A boot refusal must be deterministic to fail loudly.” Refuted as a necessity claim.** A typed result or raised exception from an awaited session can abort startup through the same FastAPI lifespan mechanism; failure loudness is an exception/handling contract. F1 proves the present invalid event table refuses before tracker dialing, and F2 executes startup failure/cleanup paths. A session substitute introduces a new model dependency plus timeout/unavailable/malformed-result cases and loses no-I/O refusal unless the existing structural check remains. No live session boot implementation was built or timed.

4. **“Anything an audit reproduces identically has to be arithmetic, otherwise two runs cannot be compared.” Refuted.** P shows exact-tie arithmetic with different legal injected draws produces different winners. This is a stubbed nondeterministic function, not a claim about a real model’s quality. Capturing snapshot, prompt/model/settings, typed result and write receipts makes a decision trace comparable; rerunning a model is a new observation, not exact replay. Arithmetic still needs the same inputs/order/configuration and any draw outcome recorded.

Enum duplication against actual consumers

The historical counts need qualification. There are four closely adjacent workflow/admission vocabularies: `WorkflowStateKind` (seven read categories), `LifecycleStage` (three configured write intents), `QueueState` (five queue-label meanings) and `ScopeLabel` (three scope-admission labels). `LaneReportState` is a further four-state reporting vocabulary, not the three scope-terminal outcomes; KOD-781 remains the authority boundary for that distinction.

Workflow kind drives legacy openness and criterion gap; lifecycle stage resolves at `LinearMcpTracker.set_workflow_state` into configured vendor names; queue states drive scans/legacy approval and terminal queue writing; scope labels drive native scope approval. Merging these because “done”/“approved” repeat would erase different legal domains and independent mappings. Their overlap is still risky at loose boundaries: P confirms different StrEnum classes with equal string values compare equal, while identity comparisons differ. Existing consumers generally use explicit enum identity; dictionary keys or unvalidated strings need boundary scrutiny. Pydantic serialization alone does not establish nominal separation.

`WorkRefRole` has five members (deliverable, iteration, recovery, best_iteration, integration); `BranchRole` has three (deliverable, loop, recovery). They are not duplicate sets. Work refs feed base resolution/landing and durable pushed-head identity; branch associations feed run-state/lane-record history. F1 tests both vocabularies and their consumers. Unifying them would introduce loop into base-resolution inputs or integration into historical association records, or require a translating subset again. Whether “loop” and “iteration” should share a concept is not answered just by spelling overlap.

There are now **five**, not four, three-member enums whose names end in Verdict:
* `CriterionVerdict`: feasible / infeasible / unverifiable, with repair/evidence invariants and resource-unavailability semantics.
* `AdmissionVerdict`: buildable / not_buildable / unverifiable; organize routes to mark-complete, reauthor or escalate and refuses Boolean coercion.
* `AuditVerdict`: holds / refuted / unverifiable; fresh evidence and refutation/mandate actions, also refuses Boolean coercion.
* `AcceptVerdict`: accepted / ship_with_flags / rejected; two members permit shipment and the middle is not “unknown.”
* `GateVerdict`: clean / redacted / blocked; content admission permits clean or transformed payload and refuses blocked output.

F1/F3 exercise failure/repair restrictions, Boolean refusal, wire round trips, flagged acceptance and gate refusal. A generic three-state verdict cannot preserve these transition meanings without domain-specific mappings; equal cardinality is not duplicated responsibility. Grounded proposal for the founder’s next decision

The executable evidence supports treating **agent decision, validated result, and authority to perform a side effect as separately reviewable responsibilities**. This is a proposal for interpreting the KISS direction, not a new rule and not a retained/moved/retired classification.

For each named component, the founder can now decide whether its current behavioral contract remains: exact rank policy; whole-scope refusal; each exclusion and precedence; scoped versus legacy blocker meaning; configured event mapping and sole writer. If a component moves to a typed session, its report should state which existing predicates become postconditions and which are intentionally retired. There is no need to pretend that schema validation alone preserves them. Ownership can remain a tool operation invoked by an agent, and nondeterministic decisions can have replayable recorded results.

Concrete ordinary work already supported independently of that choice: preserve approved surface ownership repair, compose the scope walker while retaining current approval semantics, finish native in-memory FireSpec transport, and close the typed port failures already authorized by the user. At this baseline the composition guard still refuses a non-null scope; one-lane-per-pass source and isolated readiness tests are not proof that the production scope walk is wired. These are actionable integration facts, not reasons to stop all implementation.

The reserved follow-ons remain the actual KOD-806 blocked edges: KOD-797, KOD-795, KOD-796, KOD-798, KOD-401 and KOD-403. Approval placement/partial filtering, lane-mark carrier, stall-state interpretation and native branch-persistence choices remain with their owning contracts. This report supplies the missing evidence phase; KOD-806 is not complete until the founder’s retained/moved/retired ruling exists.
