## 4. Apply all eight review lenses to every implementation lane

Maintain a 9 × 8 coverage matrix: L1–L9 against the following lenses.

1. SOLID
Cohesive responsibilities, substitutable contracts, narrow consumer-facing
ports, and no second authority for the same responsibility.

2. DRY
One owner for each invariant and policy. Reuse mechanisms without merging
concepts that only happen to look similar.

3. Hexagonal architecture
Domain/application logic must not depend on vendor representations or
concrete adapters. Composition selects implementations.

4. KISS
Choose the smallest solution that satisfies the real contract. Delete
unnecessary machinery, speculative settings, and unused execution paths.

5. Typed agent calls instead of semantic heuristics
This is an agent-orchestration library. Prefer one structured-output agent
call through existing infrastructure over hand-built semantic rules,
substring matching, or elaborate scoring machinery.

Structured-output calls are first-class typed boundaries. Validate their
outputs and preserve types through downstream consumers.

Keep necessary identity, authorization, concurrency, and transactional
enforcement outside model judgment. Do not invent broad exceptions to the
founder’s KISS direction; justify any retained deterministic policy by its
actual contract and preserve unresolved decisions as unresolved.

6. Official framework practices
Check FastAPI, Pydantic, and LangGraph against versions resolved in uv.lock.
Use official documentation and, where needed, version-matched source.
Cover lifespan/dependencies, model validation/settings, unions, graph state,
reducers, retries, checkpointing, side-effect replay, and resume behavior.

7. Type safety
Classify every material change as improvement, neutral, or regression.
Prefer meaningful base interfaces, narrow protocols, discriminated unions,
and exhaustive handling where appropriate.
Do not use Any, unchecked casts, ignores, model-copy shortcuts, or optional
field combinations to conceal an invalid contract.

8. Repository hygiene
Keep domain types, configuration, constants, adapters, services, handlers,
prompts, and execution logic coherently placed. Avoid both dumping-ground
modules and needless fragmentation.

Every matrix cell needs evidence or an explicit not-applicable justification.
“No issue found” is a reviewed result, not the default for uninspected code.
Passing mypy/pytest does not substitute for this matrix.
